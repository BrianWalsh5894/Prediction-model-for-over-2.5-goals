# Data Dictionary — Raw Source Files

Source: football-data.co.uk, downloaded 2026-10-17
Divisions: E0 (Premier League), E1 (Championship), E2 (League One), E3 (League Two)
Seasons: 2017/18 through 2025/26

## Odds coverage by season (applies across all four divisions)

| Seasons              | Over/Under 2.5 odds available          | Betfair Exchange odds |
|-----------------------|-----------------------------------------|------------------------|
| 2017/18 - 2018/19      | None (no Avg>2.5, no BFE)               | No                     |
| 2019/20 - 2023/24      | Avg>2.5 (de-margined bookmaker average) | No                     |
| 2024/25 - 2025/26      | Avg>2.5 and BFE>2.5                     | Yes                    |

## Implication for project phases

- All 9 seasons used for training the goals/Over 2.5 model (Phase 5-8) — odds
  coverage doesn't matter here, only match results and stats.
- Baseline C (market de-margined odds, Phase 7) only usable from 2019/20 onward.
- Phase 10 (Betfair value/EV backtest) only possible on 2024/25 and 2025/26 —
  which happens to match the TEST_SEASONS already set in config.py. This is
  intentional: it's the only overlap where real BFE prices exist.
- 2017/18 and 2018/19 have no odds-based baseline comparison available —
  kept in training data regardless, since match/goal data matters more than
  odds coverage for the core model.

## Core fields present in every file

Div, Date, HomeTeam, AwayTeam, FTHG, FTAG, FTR, HTHG, HTAG, HTR, Referee,
HS, AS, HST, AST, HF, AF, HC, AC, HY, AY, HR, AR

## COVID-affected seasons

Checked directly (home win rate, avg total goals per match) across all four
divisions combined:

| Season   | Home win rate | Avg total goals | Note                          |
|----------|----------------|------------------|--------------------------------|
| 2018/19  | 0.440          | 2.660            | baseline (normal, fans present)|
| 2019/20  | 0.435          | 2.620            | partial - stoppage then finished behind closed doors; barely moved |
| 2020/21  | 0.401          | 2.479            | fully behind closed doors - clear outlier, ~8% relative drop in home win rate, ~0.15-0.18 fewer goals/match |
| 2021/22  | 0.436          | 2.605            | fans back - snapped straight back to normal |

DECISION: keep 2019/20 and 2020/21 in training data (data volume matters
more than odds/market coverage for this model), but add a
`behind_closed_doors` binary feature in Phase 5 so the model can learn
2020/21 as a different regime rather than treating it as a normal season.
Partial-impact 2019/20 may need a date-based split rather than a simple
season-level flag, since only part of that season was affected - decide
this properly when we get to Phase 5.

## xG (expected goals)

DEFERRED, not skipped. Understat (free xG source) covers Premier League
well but is patchy/absent for Championship, League One, League Two —
inconsistent across the four divisions this model targets.

Decision: build first model on shots/shots-on-target (available for all
divisions, all seasons) as the attacking-quality proxy. Revisit xG as a
Premier-League-only enhancement IF Phase 9's "performance by league"
breakdown shows PL underperforming relative to the lower divisions,
suggesting shot-count alone isn't capturing enough signal at that level.

# Data Dictionary — Clean Dataset (Phase 4)

Generated by `src/clean_data.py`, which re-runs on demand (e.g. after the
weekly update) and is safe to re-run any time. Reads the matches,
match_stats, odds, leagues and teams tables, validates them, and exports
the joined result to `data/clean/matches_clean.csv`.

## Validation performed (all passing as of 2026-10-24)

- Dates: all `match_date` values are ISO `YYYY-MM-DD`. No kickoff time is
  in the source data, so there is no timezone to standardise beyond that.
- Team/league names: standardised via `team_name_map`; 104 distinct clubs,
  no duplicate team rows, no map entry pointing at a non-existent team.
- Scores: `result` (H/D/A) agrees with `home_goals`/`away_goals` for every
  match; `total_goals = home_goals + away_goals` and
  `over_2_5 = 1 if total_goals >= 3 else 0` hold for every match (both are
  computed at import time in `import_helpers.py`, not post-hoc).
- Duplicates: no duplicate `match_id`, and no fixture (date + home + away)
  appears twice under two different match_ids.
- Row counts per league/season match the expected calendar (380 PL,
  552 Championship/L1/L2) except two known, documented cases:
  - League One and League Two 2019/20 (400 and 440 matches): season
    curtailed by COVID, finished early on points-per-game.
  - 2026/27: current in-progress season, naturally incomplete.
- No core match field (goals, result, date, target) is ever NULL.

## Known, legitimate gaps (left as NULL, never filled)

- `home_shots`/`away_shots` etc. (match_stats): NULL for 1 match in
  2018/19 — an isolated source gap.
- `avg_over_2_5`/`avg_under_2_5` (bookmaker-average odds): NULL for all of
  2017/18-2018/19 (not collected by the source for those seasons), plus 5
  isolated matches in 2019/20 and 1 in 2022/23.
- `bfe_over_2_5`/`bfe_under_2_5` (Betfair Exchange odds): NULL before
  2024/25 (not collected by the source before then), plus a handful of
  isolated matches in 2024/25-2026/27.
- None of these are imputed or guessed — they stay NULL and must be
  handled explicitly (e.g. excluded, not zero-filled) by anything that
  consumes them, per Phase 4's rule.

# Data Dictionary — Features (Phase 5)

Generated by `src/build_features.py` from `data/clean/matches_clean.csv`,
exported to `data/clean/features.csv`. Verified leak-free by
`src/audit_features.py` (see below) — run both any time the clean dataset
changes (e.g. after a weekly update).

## Leakage rule and how it's enforced

Every feature uses `.shift(1)` **before** any rolling/expanding window, so
a match's own result never contributes to its own features — only
strictly earlier matches do. This is not just asserted in a comment:
`audit_features.py` independently re-derives a random sample of feature
values (last-5/10 goals, games played, rest days, Elo) straight from
`matches_clean.csv` using a separate implementation, and fails loudly if
anything doesn't match the generated `features.csv` exactly.

**The raw post-match box score (`home_goals`, `away_goals`, `total_goals`,
shots, corners, fouls, cards, `result`) is deliberately left out of
`features.csv`.** Those columns are what `over_2_5` is computed from, so
if a training script accidentally used one as a feature it would look
like a near-perfect model instead of the bug it is. They're still in
`matches_clean.csv` if ever needed for backtesting or debugging.

`audit_features.py` also runs a correlation check against the target and
flags anything above `|corr| > 0.4` for manual review (Phase 0's "assume
any suspiciously strong result is a bug" principle, applied to features
rather than betting edges). As of 2026-10-24 nothing in `features.csv`
exceeds that — the strongest signals are the market odds (expected, and
excluded from training anyway) and pre-match shots/Elo in the 0.06-0.07
range, which is a realistic size for a single football feature.

## Column groups in `data/clean/features.csv` (119 columns, 18,526 rows)

**Identity / target** (not features): `match_id`, `match_date`, `season`,
`league_name`, `home_team`, `away_team`, `over_2_5` (target),
`behind_closed_doors`.

**Odds** (benchmarking/backtest only — Phase 7 baseline C, Phase 10 —
never a training feature): `avg_over_2_5`, `avg_under_2_5`,
`bfe_over_2_5`, `bfe_under_2_5`, `bfe_close_over_2_5`,
`bfe_close_under_2_5`.

**Team strength**: `home_elo_pre` / `away_elo_pre` — each team's Elo
rating immediately before this match (K=20, home advantage +65 Elo
points, starting rating 1500; config.py).

**Attack/defence, per side** (`home_`/`away_` prefix on each):
- `overall_<stat>_roll5` / `roll10`: last 5/10 matches, any venue
- `overall_<stat>_season_avg`: expanding average so far this season
- `venue_<stat>_roll5` / `roll10`: last 5/10 matches at THIS venue only
  (home matches only for home team's `venue_*`, away matches only for
  away team's `venue_*`)
- `<stat>` is one of: `goals_for`, `goals_against`, `shots_for`,
  `shots_against`, `sot_for` (shots on target), `sot_against`

**Form**: `over25_roll5` / `roll10` (Over 2.5 % in the team's last 5/10
matches), `points_roll5` / `roll10` (points won in last 5/10 matches),
`rest_days` (days since the team's previous match, any venue).

**Early-season blending** (edge case): `games_played_career` (matches
played before this one, ever), `season_match_num` (matches played before
this one, this season only), `prior_season_<stat>` (whole-season average
from the team's immediately preceding season — safe, since that season
has already finished), `blended_goals_for` / `blended_goals_against` /
`blended_over25_rate` (uses the current-season rolling figure once
`season_match_num >= 5`, falls back to `prior_season_*` if available,
else to the league-wide running average — `league_over25_avg_to_date` /
`league_goals_avg_to_date`, itself computed leak-free from only earlier
matches in that league).

**Match-level**: `combined_home_goal_rate` / `combined_away_goal_rate`
(simple Poisson-style expected-goals proxy: attacking side's overall
10-match scoring rate averaged with the defending side's 10-match
conceding rate), `league_Premier League` / `league_Championship` /
`league_League One` / `league_League Two` (one-hot).

**Training eligibility** (edge case): `eligible_for_training` = 1 only
when both teams have at least `MIN_GAMES_CAREER_FOR_TRAINING` (3, in
config.py) career matches already played — 18,352 / 18,526 matches
qualify. This flags rather than drops rows, so Phase 8 can decide whether
to exclude them.

**Promotion/relegation** (edge case): handled by construction, not a
separate feature — `team_id` has no league attached, so a club's rolling
form carries across divisions automatically when it's promoted or
relegated. 76 of the 104 clubs in the dataset have played in more than
one of the four divisions; `audit_features.py` prints this count as a
sanity check.
